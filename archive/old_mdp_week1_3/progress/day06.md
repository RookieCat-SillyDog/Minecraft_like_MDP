# Day 06

## 今日目标

完成 Minecraft-like Make Bridge 环境的书面 MDP 定义，明确状态、动作、转移、奖励、折扣因子、初始状态和终止条件，并说明位置状态与元素状态分别提供的信息。

## 完成情况

完成了 `docs/minecraft_mdp_spec.md`，其中定义了：

- 无障碍的 $5\times5$ 地图、坐标方向及 start、wood、iron、factory 的固定位置。
- 状态 $(row,col,w,i,b)$ 中每个分量的含义和可达状态约束。
- 上、下、左、右四个动作及其编号，与第一周 GridWorld 保持一致。
- 确定性移动、越界原地不动、自动收集资源和进入 factory 后合成 bridge 的转移顺序。
- 每步奖励 $-1$、折扣因子 $\gamma=0.95$、初始状态 `(0, 0, 0, 0, 0)` 和唯一可达终止状态 `(4, 4, 1, 1, 1)`。


原始候选空间包含 200 个元组。根据自动收集和立即合成的约束，书面推导得到 96 个预期可达状态。

## 验证结果

对照两周任务书与统一接口逐项检查，当前规格包含 $S,A,T,R,\gamma$、初始状态和终止条件。转移模型对每个非终止状态和合法动作只给出一个概率为 1 的下一状态，因此概率总和为 1。

两条任务顺序在定义上均成立：

```text
start -> wood -> iron -> factory
start -> iron -> wood -> factory
```

当前仅完成书面模型，尚未实现 `env/minecraft.py`，因此没有声称环境测试已经通过。96 个可达状态也是待独立验证的预期值。

## 遇到的问题

状态元组中的 `b` 在当前最小任务中存在冗余：完成 bridge 后立即终止，而且唯一完成位置是 factory，所以可达状态中的 `b` 可以由位置、`w` 和 `i` 推导。任务书明确要求保留 `b`，本规格将它作为显式任务完成标志，并在文档中说明了这一限制，没有把它误写成当前环境满足马尔可夫性质的必要变量。
