# 第三周思考题

联合状态记为

$$
x=(l,k,b), \qquad c=(k,b), \qquad x=(l,c).
$$

两种写法指的是同一个联合状态，区别只在于后续分析是否保留 $k$ 与 $b$ 的内部结构。

## 1. 为什么 $(l,k,b)$ 构成 Markov state，而单独使用 $l$、$k$ 或 $b$ 通常不满足 Markov 性质？

Markov 性质要求：给定当前状态和动作，下一状态、即时奖励、合法动作与是否终止都不再依赖更早的历史。$(l,k,b)$ 恰好穷尽了所有转移规则和终止谓词会读取的变量，因此是本环境的 Markov state。

单独拿任何一个因子都不够。位置相同而钥匙不同，同一扇门可能一边能过、一边不能；牛肉状态相同而位置不同，`cook` 可能只在厨房可用。只看 $k$ 或只看 $b$ 也一样——总会漏掉其他规则要读的变量。观测值相同、合法动作或后继却不同，这样的量撑不起 Markov 性质。

## 2. 为什么 $c=(k,b)$ 仍然有价值？为什么它不能取代对 $k$ 与 $b$ 的显式分解？

$c=(k,b)$ 的价值在于把“位置之外的对象状态”收拢成一个单元，方便讨论同一张位置图在不同对象上下文中的表现，也延续了上一版的 location-context 记法。

但它不能上升到不可再分的 81 状态节点。钥匙动作只改 $k$，牛肉动作只改 $b$，第一版的依赖也只有 $K\to L$ 和 $L\to B$ 两个方向；把这些结构塞进一个整体变量里就全被掩盖了。显式保留 $k$ 与 $b$，才能表达因子不变性和稀疏依赖，才能把一条钥匙转移复用到不同牛肉状态、把一条牛肉转移复用到不同钥匙状态。$c$ 是方便的分组，不是独立的状态空间。

## 3. “将状态写成三个坐标”和“跨 context 共享 component transition”之间有何本质区别？

写成 $(l,k,b)$ 只是给联合状态编了三个坐标，本身不带来任何经验共享。平坦联合表示同样用这个三元组做索引，照样为 729 个联合状态各学各的转移。

跨 context 共享 component transition 是另一层面的主张：某个因子的转移规律在其余因子的不同取值之间保持不变。比如第一版的钥匙转移满足 $F_K(k,a_K)$，在某个 $(l,b)$ 上学到的钥匙动作可以直接迁移到其他 $(l,b)$。共享也不是无条件的——位置转移是否可用仍可能读 $k$，牛肉转移是否可用仍可能读 $l$。简言之，三坐标是状态的记法，跨上下文共享是对转移规律的结构性约束，二者不能混为一谈。

## 4. 分别给出 $K\to L$ 和 $L\to B$ 的具体例子，说明条件因子和被改变因子

$K\to L$ 的例子是双向钥匙门。钥匙状态 $k$ 是条件因子：门的开合读取钥匙头与钥匙柄的谓词；穿过门的动作属于位置动作，执行后 $l$ 改变，$k$ 和 $b$ 不动。

$L\to B$ 的例子是功能区限制。位置 $l$ 是条件因子：`cook` 要求在厨房，`cut` 要求在切菜板；两个动作属于牛肉动作，执行后分别推进 $b_c$ 与 $b_d$，$l$ 和 $k$ 不动。

记号 $S_{i\to j}$ 和 $K_{i\to j}$ 中箭头的方向与之一致：左侧是规则读取的条件因子，右侧是动作实际改变的因子。

## 5. 为什么两个方向的 schema count 都是 2，但 grounded template count 不相同？

本实现把耦合计在两个层级上：$S_{i\to j}$ 数受另一因子影响的动作模式，$K_{i\to j}$ 数具体的有向转移 $(s_j,a_j,s'_j)$。

钥匙门控制 `left`、`right` 两个位置动作模式，也只对应门的两个方向，于是 $S_{K\to L}=2$、$K_{K\to L}=2$。功能区控制 `cook`、`cut` 两个动作模式，故 $S_{L\to B}=2$；但每个模式展开为 6 条源、目标各异的转移，故 $K_{L\to B}=12$。

两个数字回答的问题不同：前者是“有多少类操作依赖另一因子”，后者是“有多少条具体转移依赖另一因子”。前者保住了两种操作的对称性，后者如实反映了牛肉图的阶段化结构。

## 6. 存在一扇钥匙门，但所有最短路径都绕开它：它增加了什么？

两件事都发生了，但要分开说。

结构耦合是环境层面的属性：只要门规则存在，$S_{K\to L}$ 和 $K_{K\to L}$ 就会计入它，与任何具体 query 无关。

而该 query 的必需耦合没有增加：所有最短路径都绕开了门，则

$$
\mathcal R_{K\to L}(q)=[0,0].
$$

环境“具备”这条耦合规则，但解决这个 query 的任何最短方案都“用不到”它。换一对起点和目标，同一扇门就可能变得绕不开。

## 7. 比较耦合复杂度时，为什么必须单独控制最优原语路径长度 $L^*$？

路径长度本身就是任务难度的一部分。路径越长，动作越多，遇到耦合规则和切换动作域的机会通常也越多；在每步奖励 $-1$、$\gamma=0.95$ 的设定下，长度还直接决定回报。

若两个 anchor 的 $L^*$ 不同，表现差异就说不清是来自耦合结构，还是单纯多走了几步。所以应先在指定比较中把 $L^*$ 匹配齐，再看路径耦合和动作域切换。当然 $L^*$ 也不是唯一的干扰源——最短路径数量、分支因子、动作可用性和可达状态数都要一并报告。

## 8. 存在多条等长最优路径时，为什么不能只报告 PI 或 VI 选出的一条？

PI 和 VI 求出的最优价值没有问题，问题出在提取路径这一步：多个动作价值并列时，选哪个动作取决于固定动作顺序和 tie-breaking 规则。这样得到的只是“某个”最优解，不是最优解的全貌。

而不同的等长最优路径可能用不同次数的钥匙门、功能区规则或动作域切换。只报一条，等于把实现中的并列偏好误当成任务的属性。正确做法是在 shortest-path DAG 上对所有最短路径计算

$$
\mathcal R_{i\to j}(q)
=
\left[
\min_{\tau\in\mathcal T^*(q)}N_{i\to j}(\tau),
\max_{\tau\in\mathcal T^*(q)}N_{i\to j}(\tau)
\right]
$$

以及 $D(\tau)$ 的范围。这样得到的区间不再依赖 PI 或 VI 碰巧选了哪条并列路径。

## 9. 如何设计 held-out $(l,k,b)$ recombination，以区分三类学习者？

held-out recombination 的要点是：测试阶段不引入新的因子节点、动作、单因子边或耦合规则，只把训练中没有共同出现过的 $l$、$k$、$b$ 重新拼在一起——考的是组合迁移，不是学新东西。

可以设两类测试：

1. **无耦合重组**：训练分别覆盖测试所需的三类单因子转移，但留出它们的某些联合组合。平坦学习者没见过完整联合状态，预计难以直接迁移；对象分离学习者和稀疏三因子学习者都能复用已学的单因子转移。
2. **耦合规则重组**：训练中见过某条 $K\to L$ 或 $L\to B$ 规则，测试把同一条规则放进未见过的联合上下文。只分离了对象、没表示方向性依赖的学习者会在新的门控组合上失手；稀疏三因子学习者应能同时复用单因子转移和门控关系。

由此得到三类模型的区分性预测：平坦学习者主要看完整 $(l,k,b)$ 是否见过；对象分离学习者能通过无耦合重组这一关，但对新门控组合缺乏系统迁移；稀疏三因子学习者在规则本身已学过的前提下两类都能完成。还可以只在训练中展示部分 `cook` 或 `cut` 阶段，测试留出同一动作模式的其他阶段，以检验学到的是 schema 还是背下了具体模板。对照组须匹配训练暴露次数、奖励、目标、动作集合和 $L^*$，免得把熟悉度或路径长度错当成表示差异。

## 10. 构造一个不连通的因子图，说明为什么必须使用 BFS

保留钥匙图全部 9 个理论节点，但删掉所有进入 $k=(2,2)$ 的有向边，并选一个别的初始钥匙状态。于是 $(2,2)$ 还躺在节点表里，却从初始状态永远到不了。

此时直接对三张节点表做笛卡尔积，程序仍会枚举出全部

$$
9\times 9\times 9=729
$$

个联合状态，其中钥匙为 $(2,2)$ 的 81 个全是虚假状态。BFS 从初始联合状态出发，只沿实际合法动作和转移扩展；在其余两个因子 9 个状态都可达、其余 8 个钥匙状态也可达的前提下，得到的是

$$
9\times 8\times 9=648
$$

个。这个反例说明“满足类型和规则定义”不等于“从本任务初始状态实际可达”，`states` 应该指后者。

## 11. 什么样的结果会削弱“人类会分别抽象位置、钥匙与牛肉”这一假设？

分离假设最直接的预测是：参与者能把学过的单因子转移迁移到未见过的 $(l,k,b)$ 组合。如果在训练覆盖充分、$L^*$ 和暴露次数都受控的条件下，这种重组优势仍然稳定缺席，假设就危险了。

更强的反证包括：错误与反应时主要由完整联合状态是否出现过来解释；改变无关因子对迁移的破坏不亚于改变目标因子；平坦模型或不可分解的 81 状态 context 模型在选择、学习曲线和反应时上持续胜过对象分离与稀疏三因子模型。

单次不显著不足以否定假设——训练不足、样本量小或测量不敏感都会造成空结果。真正有分量的证据是：在多个预先规定的留出重组条件中反复缺少因子迁移，同时替代模型稳定给出更好的样本外预测。

## 12. 为什么动作名称、转移模板和完整联合状态中的具体转移实例不是同一个计数单位？

三者层层加细。动作名称是最粗的单位：`cook` 只有一个名字。模板加上源状态和目标状态：`(0,0) --cook--> (1,0)` 与 `(1,0) --cook--> (2,0)` 是两条模板。转移实例再加上其他因子的 context：同一条牛肉模板在不同钥匙状态下执行，各算一个实例。

它们分别回答“有多少类操作”“有多少条因子内规则”“这些规则在多少个 context 中实际出现”。混用同一个数字，就会得到互不兼容的解读。

## 13. $S_{i\to j}$、$K_{i\to j}$、$M_{i\to j}$ 与 $N_{i\to j}(\tau)$ 分别回答什么问题？

四个量各管一层：$S_{i\to j}$ 数受因子 $i$ 影响的 factor-$j$ 动作模式；$K_{i\to j}$ 数受影响的有向模板；$M_{i\to j}$ 数这些模板在 factor-$i$ context 中的合法实例化次数；$N_{i\to j}(\tau)$ 数某条实际路径用了几次耦合模板。

以 `location_gates_beef` 为例：`cook` 和 `cut` 都受位置限制，$S_{L\to B}=2$；两者合计展开为 12 条牛肉模板，$K_{L\to B}=12$；每条模板只在唯一的功能区位置合法，$M_{L\to B}=12$；从 $(0,0)$ 到 $(2,2)$ 要两次 `cook` 加两次 `cut`，每条最短路径都有 $N_{L\to B}(\tau)=4$。四个数相互关联，但谁也替代不了谁。

## 14. 为什么钥匙门可以改变 location cluster 的内部拓扑，却不一定是一条 cross-cluster location edge？

在位置划分 $\Pi^L$ 中，cluster 固定 $k$ 与 $b$、只让 $l$ 变。穿门的动作恰好只改 $l$，所以这条边完全留在同一个 location cluster 内部，不是跨 cluster 的边。

但门的可执行性随钥匙状态变化：满足谓词的 cluster 含门边，不满足的没有。于是不同钥匙状态对应的 location cluster 内部拓扑不同——这种“内部转移规律随另一因子变化”正是 $K\to L$ 耦合。可见跨 cluster 边的分类替代不了方向性耦合分析。
